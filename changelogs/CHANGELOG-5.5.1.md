# Changelog - 5.5.1

> 发布日期：2026-08-08

## 概述

5.5.1 修正壁纸切换命令在 IPC 等待层的超时语义：慢不等于失败。  
权威结果仍是内部状态更新与 `WallpaperChanged` / `ModeChanged` 事件；等待过久只作为性能信号记录日志。

建议与 `lianwall-gui ≥ 1.4.4` 配套使用，以获得完整的「切换中 → 事件完成」交互。

---

## 问题修复

### 1. 壁纸类命令不再因回执等待超时返回业务 Error

**问题**：
- 连接层对 `Next` / `Prev` / `SetWallpaper` / `SetMode` 使用短超时（约 5–10 秒）等待命令队列回执
- `mpvpaper` / `awww` 稍慢时，客户端收到 `Error { code: timeout }`
- 命令队列中的切换往往仍在继续并最终成功，导致「报错了但壁纸已经换了」

**修复**：
- 上述壁纸类命令改为等待真正完成，不再因等待超时返回 `Timeout` 业务错误
- 超过约 5 秒仍在执行时，周期性输出性能探针日志（`still in progress`）
- 完成后若耗时超过阈值，记录 `finished slowly` 警告（性能信号，非失败）

**效果**：
- GUI / CLI 不会再把「引擎慢」误当成「切换失败」
- 业务成功路径与事件推送保持一致
