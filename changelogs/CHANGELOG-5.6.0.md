# Changelog - 5.6.0

> 发布日期：2026-11-12

## 概述

5.6.0 继续使用 awww/mpvpaper，集中修复引擎调用、状态同步、脚本接口和文件可靠性。
请与 **lianwall-gui 1.6.0** 配套升级。自研渲染后端留到后续 **6.0.0**。

## 引擎与生命周期

- 直接检查 PATH 中可执行文件及配套 daemon，不再依赖系统安装 `which`。
- awww 使用独占命名空间，轮询 query 确认就绪；图片命令有期限并保留错误详情，特殊字符路径按独立参数传递。
- mpvpaper 冷启动通过私有 IPC 查询视频参数确认解码就绪；失败保留旧进程，不再将 spawn 成功/日志出现等同于加载成功。
- 默认冷启动切换准备新进程后再替换旧进程；只结束本 daemon 创建的进程组，避免全局按名称 pkill。
- mpv 参数值正确编码空格与引号，精确识别 vf/IPC 选项；拒绝破坏进程所有权的 fork 参数。
- 可选热换片等待 `file-loaded`，不再仅凭 loadfile 接受回执提交成功；IPC 文件按 inode 核对归属后清理。
- 引擎调用集中到 daemon 后端模块，删除未使用的旧 core 生命周期实现。
- 历史前进/后退、选择器冷却/指针及 VRAM 模式变化在成功后提交，失败不伪造新壁纸状态。

## 通信、状态与脚本

- 修复分段请求遇到事件推送时丢数据，以及慢命令阻塞同连接查询/事件。
- 带 ID 回执独立匹配，旧客户端保留 FIFO；请求、等待任务与写出均有资源边界。
- daemon 防止重复启动抢占 socket，安全回收残留端点，所有权保持至关闭清理结束。
- 轮换期限更新后推送状态；同值间隔写入不重置计时，暂停以 null 表达，修复可用数量重复扣减。
- CLI 订阅使用 NDJSON，成功订阅后允许无限空闲；异常断线返回非零码，不自动重放命令。
- 配置 get/set 在线离线类型与校验一致；配置读取错误不再静默连接默认 socket。
- hook 超时/取消清理自有进程组，输出和队列有界；所有关闭来源共用 cleanup 预算。
- 配置、权重与首次 hook 模板原子写入；保存失败不提交内存或事件，临时暂停不泄漏到磁盘。

## 升级注意事项

- `image_engine.swww_args` 改为 **`image_engine.awww_args`**。旧 TOML 首次读取时备份到追加 `.pre-awww.bak` 的文件后迁移；两键冲突拒绝加载，已有备份不覆盖。只读配置允许内存迁移。
- CLI/socket 不保留旧键别名，GUI 和外部脚本需同步更新。
- JSON 业务/参数错误改为 **stdout JSON + 非零退出码**；读取 stderr 的脚本请迁移。help/version 保持文本。
- `paths.mode` 表示启动偏好；切换当前模式使用 `lianwall mode` / SetMode。
- mpvpaper 不允许 `--fork/-f`；默认使用私有 IPC 做就绪检测，但仍每次冷启动，避免长期复用引入资源累积。
- 自定义 `ipc_socket` 或手动 IPC 参数使用固定地址时，冷启动回退需先释放旧进程，不保证失败保留旧画面；未知现存路径不覆盖。
- legacy swww 仍可回退；已有外部 swww-daemon 时拒绝接管。现代 awww 需支持 `--namespace`。

## 验证与支持范围

完整 Rust 回归、隔离假引擎场景及 Release 构建通过。当前 Hyprland 上已验证真实 awww 0.12.1 / mpvpaper 1.9：图片/视频/IPC 切换、特殊路径、损坏视频失败保留旧画面、循环存活及退出清理。

主要维护作者使用的 Linux/Hyprland 环境，不再承诺全 Wayland、所有 Linux 发行版或 BSD。
Fedora、其他合成器、不同显卡组合和长时间内存表现尚未完成完整验收。
